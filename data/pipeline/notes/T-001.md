## DAG rationale

Every prerequisite edge points from a strictly lower `order` to a higher one, so the graph is trivially acyclic (lesson order is itself a topological ordering). Edges encode conceptual dependencies:

- **Linear spine (beginner):** setup → syntax → types → {strings, control-flow} → loops → functions → collections → I/O.
- **OOP thread:** functions + dicts → classes-and-oop → oop-advanced → architecture-patterns; dunder methods make context-managers reachable from classes + error-handling.
- **Functional thread:** functions + lists → functional-idioms → decorators (closures/first-class functions required).
- **CS-fundamentals thread:** core collections → data-structures-and-complexity → core-algorithms and memory-and-performance (complexity analysis underpins both).
- **I/O thread:** basic-io + error-handling → file-io → concurrency-threads (I/O-bound work demos) → asyncio.
- **Engineering thread:** functions → modules-and-packages; error-handling + modules → testing-basics; testing + architecture-patterns → capstone-project.

No self-references, no cross-curriculum references, all 28 orders unique and positive.
