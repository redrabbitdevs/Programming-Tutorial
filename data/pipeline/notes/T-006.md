## Sample-development decisions

- **py-050-refcount prints deltas, not absolute counts.** The 3.14 whatsnew notes that CPython now avoids some internal refcount bumps, so `sys.getrefcount()` values can shift across versions; the sample compares before/after readings (aliasing adds exactly one reference) so the fixture stays stable while still teaching the rule.
- **py-051-gc-cycles** originally printed `gc.collect()`'s return count, which varies with interpreter state (local captured `2`; CI runners got `23` — failed sample matrix on head 052ba7c). Reworked at head 356eaf4: weakref handles to each cycle object, `del` the strong refs, `gc.collect()`, then print liveness (`cycle collected: True`) — deterministic by construction (byte-identical across 7 fresh-interpreter runs; Code Validator attestation).
- **py-055-pool-map**: worker function is top-level (picklable) and the pool code sits under the `__main__` guard — required where workers start fresh rather than copying parent state (forkserver/spawn). `pool.map` preserves input order, so output is deterministic.
- **Thread samples print only after `join()`**, so OS scheduling cannot affect captured output; py-054 relies on Queue FIFO ordering (deterministic by construction).
- **Asyncio samples**: no timing values in output; the one completion-order claim (py-057) uses distinct sleep durations, and `gather` returns results in argument order regardless of finish order.
- **Capstone py-063** drives `parser.parse_args(argv)` with explicit argument lists against a shared store — zero real argv at runtime, no persistence, while still exercising five command lines including the KeyError→`"error: …"` boundary path.
- No untagged python snippets in the batch (every runnable fence is a tagged sample); all prose-level API mentions (`gc.get_threshold()`, `cProfile`, `asyncio.to_thread`) are inline names without fenced code.

## Version verification (fetched 2026-11-20 against official Python 3.14 docs)

- **`docs.python.org/3.14/library/gc.html`** — `gc.collect()` return value ("sum of collected objects and uncollectable objects"), three-generation model, threshold semantics (`get_threshold()`), free-threaded-build note. All L24 claims match.
- **`docs.python.org/3.14/whatsnew/3.14.html`** — "Garbage collection" section: the incremental GC shipped in 3.14.0–3.14.4 was **reverted in 3.14.5** to the generational GC from 3.13 (gh-142516). L24 therefore describes the current generational behavior and carries **`minLangVersion: "3.14"`**. Same page: PEP 779 — free-threaded builds are officially supported in 3.14 while the default build remains GIL-enabled (single-threaded penalty ~5–10%); L25's GIL section matches and carries **`minLangVersion: "3.14"`**. Also: multiprocessing's default Unix start method is now `forkserver` (spawn on Windows/macOS) — L25's wording is deliberately platform-neutral ("on platforms where workers start fresh…").
- **whatsnew "Optimizations"** — CPython avoids some internal refcount modifications, so `sys.getrefcount()` values may differ from earlier versions → py-050 uses deltas (see above).
- Long-stable APIs, no version-sensitive claims: `asyncio.run` / `gather` / async generators (L26), `typing.Protocol` + `runtime_checkable` and `abc.ABC`/`@abstractmethod` (L27 — the abstract-instantiation `TypeError` message was captured verbatim from a 3.14.10 run, not transcribed from memory), argparse subparsers with `required=True` (L28).
