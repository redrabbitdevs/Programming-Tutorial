## Key implementation decisions

- **Trailing slash** — `astro.config.mjs` sets `trailingSlash: 'always'` (was the `ignore` default). Generated canonical URLs now carry the trailing slash, so Astro-emitted links and the dashboard's hand-written `/learn/.../NN-slug/` hrefs agree exactly. Output file layout is unchanged (`<route>/index.html`); all pre-existing e2e URLs already use slashed forms.
- **Single h1** — lesson bodies open with a `# Title` duplicating the layout's canonical `<h1>` (style guide: single h1 = title). A scoped mdast plugin (`stripLessonH1`) registered on the Sätteri processor removes depth-1 headings **only for files under `src/content/lessons`**; every other markdown is untouched. Verified: exactly one `<h1>` per built lesson page.
- **Markdown pipeline (Astro 7)** — Astro 7's default processor is Sätteri; legacy `markdown.remarkPlugins` hard-fails without the no-longer-default `@astrojs/markdown-remark`. No new dependency added: the config sets `markdown.processor: satteri({ mdastPlugins: [stripLessonH1] })` using `@astrojs/markdown-satteri`, which is already installed as Astro's own default-processor dependency.
- **Content fix (1 line, flagged for Editorial)** — `01-python-setup.mdx:23` used a `<https://…>` angle-bracket autolink, which MDX parses as JSX and rejects at build (latent: these files had never been rendered before T-007). Converted to the equivalent explicit link `[https://www.python.org/downloads/](https://www.python.org/downloads/)` — identical rendering. It was the only occurrence in all 28 lessons (scanned).
- **Article typography** — Tailwind v4 preflight resets headings/lists/paragraphs, so MDX lesson bodies rendered as flat text on first build. Added `.pt-article` scoped content styles in `global.css` (h1–h3 scale one step under the layout's `text-3xl` h1, list markers restored, inline code chip, table borders, blockquote, links) using semantic tokens only; `Lesson.astro` wraps the slot in `<div class="pt-article">` so checkbox/nav chrome is unaffected.
- **Curriculum loading** — track hub reads `data/curriculum/*.json` via `import.meta.glob` (same pattern as the dashboard), with the glob inside `getStaticPaths` because Astro splits that function into a separate prerender module (top-level frontmatter helpers are not visible there).

## Known limitations

- **CTA in mixed published states**: per spec the static CTA targets the lowest-order *unpublished* lesson; until that lesson's route ships, the client script immediately retargets the link to the next available published (unchecked) lesson, so users never hit a 404. The current all-published state exercises only the "Track complete" branch.
- **Sample-output appendix**: each lesson page appends a "Sample outputs" section repeating every tagged sample's fixture output after the body (the body already shows code + inline expected output pedagogically). This is the spec-mandated fixture-backed rendering; it intentionally does not appear in the TOC (TOC headings come from the MDX render only).
- **axe coverage is light-theme**: Playwright runs with the default light color scheme, same as all prior gate audits; dark-theme contrast relies on the token-pair verification recorded in `tokens.css` and the dual Shiki theme.
- **Track hub CTA label vs live target**: after a user checks off lessons on a complete track, the link follows their progress while the label stays "Track complete" (label reflects build-time published state; target reflects completion).
