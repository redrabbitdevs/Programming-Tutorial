# Lists & Tuples

A single variable holds one value; most real data comes in groups — scores, names, coordinates. A **list** is an ordered, changeable collection written with square brackets; a **tuple** is an ordered, fixed collection written with parentheses. Both are indexed from 0 and sliced like strings.

## Creating and indexing lists

```python
colors = ["red", "green", "blue"]
print(colors[0])    # red
print(colors[-1])   # blue
```

Lists mix types freely — `[1, "two", 3.0]` is legal, though keeping one type per list keeps your code easier to reason about. `len()` gives the count; `in` tests membership: `"red" in colors` is `True`.

This sample walks through the core operations:

```python sample=py-014-list-ops
scores = [72, 85, 91]
scores.append(64)
print(scores)
print("first:", scores[0], "last:", scores[-1])
print("middle:", scores[1:3])
scores.remove(64)
scores.sort()
print("sorted:", scores)
print("count:", len(scores))
print("has 91?", 91 in scores)
```

```text
[72, 85, 91, 64]
first: 72 last: 64
middle: [85, 91]
sorted: [72, 85, 91]
count: 3
has 91? True
```

`append(x)` adds one item to the end; `remove(x)` deletes the first occurrence of a value. Slicing (`scores[1:3]`) returns a *new* list with the items from index 1 up to, but not including, index 3 — the same stop-excluded rule as strings and `range`.

## Changing lists

Lists are **mutable**: you can change them in place. Assignment by index replaces one item (`scores[0] = 80`), and the common methods mutate the list itself:

```python
numbers = [3, 1, 2]
numbers.sort()          # numbers is now [1, 2, 3]
print(numbers)
```

Note that `sort()` returns `None` — it rearranges the list in place and hands nothing back. If you want a *new* sorted list without touching the original, use the built-in `sorted(numbers)`, which returns a fresh list.

## Tuples

A **tuple** is like a list you cannot change: no `append`, no item assignment, no `sort`. You create one with parentheses (or commas alone), and it stays exactly as written for its whole life:

```python
origin = (0, 0)
size = (width, height)   # often how you bundle a fixed pair
print(origin[1])
```

Because a tuple's contents never change, Python can treat it as a reliable fixed record — a coordinate, an RGB color, a database row. The one oddity: a single-element tuple needs a trailing comma, because `(42)` is just `42` in parentheses. Write `(42,)`.

## Unpacking

Both lists and tuples can be **unpacked** — spread across several variables in one assignment. The counts must match:

```python sample=py-015-tuple-unpack
point = (3, 7)
x, y = point
print("x:", x, "y:", y)

pairs = [(1, 2), (3, 4)]
for a, b in pairs:
    print(a + b)
```

```text
x: 3 y: 7
3
7
```

`x, y = point` binds `x` to the first item and `y` to the second — no indexing needed. Inside the loop, each tuple `(1, 2)` is unpacked into `a` and `b` before the body runs, which is why the loop variable can be two names instead of one.

<Callout type="tip">Rule of thumb: use a list when the collection grows, shrinks, or gets reordered while the program runs; use a tuple when the items are fixed by definition. Functions that return several related values often return a tuple — `x, y = get_position()` reads naturally.</Callout>

## Common mistakes

- **Index out of range**: `colors[3]` on a 3-item list raises an `IndexError`. Indices run from 0 to `len(colors) - 1`.
- **Expecting `sort()` to return the sorted list**: it returns `None`; the original list is what changed. Use `sorted(...)` when you need a new list.
- **Forgetting the trailing comma**: `(42)` is an int, not a tuple; `(42,)` is a 1-item tuple.
- **Trying to change a tuple**: `point[0] = 5` raises a `TypeError`. Rebuild a new tuple or convert with `list(point)` first.

## Summary

- A list (`[...]`) is an ordered, mutable collection; a tuple (`(...)`) is the same shape but immutable.
- Index from 0 (or negatively from -1), slice with `start:stop` (stop excluded), and measure with `len()`.
- Lists change in place via item assignment and methods like `append`, `remove`, and `sort`; `sorted()` returns a new list instead.
- Unpacking assigns each item of a list or tuple to its own variable — handy for coordinates and loop variables.
